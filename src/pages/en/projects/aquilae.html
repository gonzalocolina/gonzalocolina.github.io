Aquilae

A browser-based, turn-based strategy game for reviewing Roman history and Latin. The class splits into teams that share out the provinces of the Empire on a real map; to conquer an enemy province, a team must answer a question correctly. It has been tested in 3 schools with secondary and sixth-form students.

Problem

The game had to run on school computers, where you often cannot install anything or create accounts. Teachers also had to be able to prepare their own questions without programming, and the same game had to work for any topic or subject.

How it is played

  1. Pick 2 to 4 teams and load the questions: your own file or the sample bank.
  2. Provinces are dealt at random and each starts with 3 troops.
  3. On its turn, a team attacks from a province with at least 2 troops into a neighbouring enemy province, by land or by sea. It can choose on the map, which highlights valid targets, or in the side panel.
  4. A question appears. The teacher reveals the answer and marks it right (the province is conquered) or wrong (the attacking province drops to 1 troop).
  5. The team that conquers the whole Empire wins, or the team with most troops if the questions run out.

Technical decisions

  • One HTML file per tool, no build step. It works by opening it in a browser, with no server or database. That fits school computers best.
  • A real map. Leaflet with the Roman provinces as GeoJSON from klokantech/roman-empire.
  • Computed, not hand-written, adjacency. Turf.js (booleanIntersects) decides which provinces share a border. Sea routes are drawn as curves and checked so they never cross land.
  • JSON question banks validated on load. Format, required fields and duplicate IDs are checked. The editor creates, duplicates and validates banks without touching JSON; the sample bank has 249 questions about Rome.
  • Games that span several lessons. A game is saved to a file and resumed in the next session. The teacher can adjust the troops of any province.
  • Built for projectors, desktops and phones. On narrow screens the game panel moves to the bottom. It is deployed to GitHub Pages with GitHub Actions.

Limits

  • One device. Having no server keeps everything simple, but the game is played on a single screen (usually the projector), not on each team’s phone.
  • The teacher referees. Answers are not marked automatically: questions are open-ended and the teacher decides whether each answer is right or wrong.
