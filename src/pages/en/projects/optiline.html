Optiline

A UCI chess engine that pairs modern alpha-beta search with a quantised neural network, plus the full pipeline that trains, validates and promotes those networks. It plays at ~3100 Elo on Stockfish 18’s scale at 100 ms per move.

Problem

I wanted a strong engine that runs on ordinary machines, laptops rather than server farms, and above all a reliable way to know whether each change makes it stronger. Intuition is misleading in computer chess: a change that looks like an improvement often loses Elo, and a network with lower validation error can play worse.

So the project has two halves of equal weight: the engine, and the system that decides what goes into it.

Approach

The engine

  1. UCIoptions, time control
  2. PVS searchiterative deepening
  3. Move generationbitboards · TT · SEE
  4. NNUE evaluationint16 · AVX2
  • Search: PVS with aspiration windows and the pruning set of modern engines: late move reductions, null move, futility, razoring, ProbCut, SEE pruning and singular extensions. Every technique can be switched on or off over UCI to measure what it contributes.
  • Move ordering: killers, capture and continuation history, countermoves and a history indexed by threatened squares.
  • Evaluation: a (768→1024)×2 network with SCReLU activation and 8 material output buckets, quantised to int16. Accumulators update incrementally with hand-written AVX2 kernels.

The training and promotion loop

  1. Dataself-play · public binpacks
  2. Trainingbullet (GPU) · NumPy with QAT
  3. Quantised exportint16
  4. ValidationC++ = float reference
  5. SPRTfull games
  6. Promotion gateone change · hashed evidence

If the network fails the SPRT, it goes back to data. If it passes, it becomes the new baseline and the experiment is archived.

  • A network is only promoted if it wins games. Validation error is used to reject broken networks, never to accept good ones. The decision comes from a full-game SPRT run with fastchess against the current baseline.
  • Immutable evidence. Each experiment lives in experiments/YYYYMMDD_* with a manifest.json (SHA-256 of the engine and the opening book, seed and concurrency) and a report.md. Reference Stockfish binaries are pinned by hash.
  • One change at a time. promotion_gate.py rejects a promotion that changes more than one UCI option.
  • Testing: GoogleTest (perft, board, NNUE, search, SEE, TT), Python contract tests and a CI matrix with four configurations: Release, ASan+UBSan, TSan and stats.

Results

The current network was trained on 8 billion positions from Stockfish’s public binpacks. These are its games against Stockfish 18 limited to different levels, at 100 ms per move:

Unlimited Stockfish 18 (100 games)1-25-74−323 ± 64

  • The two nearest rungs put its strength between 3025 and 3150 on that scale: ~3100 ± 35. The previous 768×128 network plays at about 2400 with the same search.
  • Against that previous network, the new one passed the [0, 5] SPRT at 8+0.08 with 293 wins, 1 draw and 0 losses.
  • That SPRT was won almost entirely by adjudication, so I re-checked its 12 adjudications with Stockfish 18 at depth 20: in every one the winner was at least 8.4 pawns ahead or had a forced mate. None was a false win.

UCI_Elo is calibrated at longer time controls and is not a CCRL rating. Read these numbers as positions on one ladder, not as absolute ratings.

In the browser

The Play page runs Optiline compiled to WebAssembly with Emscripten, inside a Web Worker on a single thread, because GitHub Pages cannot send the headers WebAssembly threads need. The network’s AVX2 kernels have an equivalent SIMD128 version that produces exactly the same search, node for node.

To find out what that gap costs in strength, I played the native engine against itself with the same time handicap: at 100 ms versus 64 ms, the slower side loses −40 ± 7 Elo (1,600 games). Without SIMD the loss grows to −311 ± 51.

Problems I solved

  • Truncated games. The first ablation runs stopped games after 60 plies (30 moves each), and about 90% ended as adjudicated draws: they could not tell real strength apart. They are now telemetry only, and the gate uses full games.
  • A lying meter. The old runner cut games at 120 plies and scored unfinished ones as draws. With the current method, the previous network’s edge over the 2200 rung went from +38 to +207.
  • SPRTs without a verdict. The match script could not parse fastchess’s LLR line, so SPRT JSON files were saved without their decision. I fixed it and added a test for that output.
  • Lower error is not more Elo. A network can have lower validation error and still play worse. Hence the project rule: loss can reject broken networks, but it never promotes one.

Next steps

  • Move the WebAssembly build this site uses into the Optiline repository and publish it with every release.
  • Measure the browser build’s strength directly, not only through a time handicap.
  • Continue v0.13: more data and SPSA tuning of the search.
